# Research Watch: codeburn — Cross-Tool AI Coding Cost Observability TUI

- Repo: https://github.com/getagentseal/codeburn (canonical org); also mirrors at https://github.com/AgentSeal/codeburn
- Also see: https://github.com/getagentseal/codeburn/blob/main/CHANGELOG.md (25 releases since 2026-04-13); https://awesome.ecosyste.ms/projects/github.com/getagentseal/codeburn

## Why this is worth watching

codeburn reached ~6k stars in under four weeks (first release 2026-04-13, v0.9.7 on 2026-05-07) — an unusually fast accumulation for a pure observability tool with no agent runtime or model execution component. It is the first cross-vendor cost observability TUI in this taxonomy to support 18+ AI coding tools simultaneously, reading session data directly from each provider's on-disk format without proxies or API keys. Its velocity is tracking alongside the multi-provider harness wave (opencode, Helmor, Vibe-Trading), but from a different angle: rather than unifying agent execution it unifies cost visibility — making it a structural peer to MCP session trackers but operating one layer above the protocol.

## What stands out immediately

- **Disk-native session ingestion across 18 providers.** Each provider exposes a different local format: Claude Code uses JSONL transcripts at `~/.claude/projects/`, Cursor uses a SQLite database, Gemini CLI stores single JSON files with embedded real token counts, Copilot uses VS Code workspace transcripts. codeburn parses all of them without wrapping, proxying, or requiring API access. The absence of a network call path is architecturally significant: there is no eavesdropping surface, no proxy reliability dependency, no token double-count introduced by a middleware layer.

- **v0.9.7 adds MCP tool coverage detection.** The 2026-05-07 release introduced a specific capability: detecting underutilized MCP servers — tools that incur tool-schema overhead in every session context even when never called. This is the first observability signal in this taxonomy that surfaces MCP overhead as a measurable cost category, not just a configuration concern. The framing in the docs ("still paying their tool-schema overhead every session") matches the L5 MCP context cost problem documented in the Awesome-Agent-Harness survey's C (context management) component analysis.

- **`codeburn optimize` (v0.7.0) as a waste-pattern scanner.** Eleven named waste patterns are checked: files re-read across sessions, low Read:Edit ratio, wasted bash output, unused MCP servers, context bloat (disproportionate input/cache tokens), session cost outliers at 2x peer average, and others. Output is a graded health score (A-F) with ready-to-paste fixes. This moves codeburn from passive dashboard to active recommendation engine — structurally adjacent to clawfit's own scoring function but at the session-telemetry level rather than the agent-selection level.

- **`codeburn yield` (v0.9.1) correlates sessions with git outcomes.** The yield command reads local git history and classifies sessions as Productive (commit landed), Reverted, or Abandoned. This is a novel observability axis: it ties cost data to actual delivery outcome, not just token counts. No comparable tool in the current watch queue performs this correlation. The claim is verifiable against any git repo — claim to inspect that the three-way classification is reliably accurate across different commit message styles and revert conventions.

- **TypeScript 70.7% + Swift 24.1% split.** The Swift fraction is exclusively the native macOS menubar widget (`codeburn menubar`). This is a similar technology split to Helmor (Rust native backend + TypeScript sidecar), reflecting a pattern in this generation of developer tools: TypeScript for cross-platform data logic, native code for the platform UI layer. Install paths cover npm, Homebrew, npx, bunx, and dx — unusually broad for a 6k-star tool, and suggests active effort to remove install friction.

- **Pricing via LiteLLM with model alias support.** Prices are sourced from the LiteLLM pricing table rather than maintained independently. A `codeburn model-alias` command (v0.8.7) handles proxy-rewritten model names that obscure the underlying billing model — a practical problem for teams behind inference proxies where the billed model name differs from the presented model name. This is a claim to inspect at the accuracy level: LiteLLM pricing tables can lag behind model provider price changes by days to weeks.

- **External security audit documented (v0.7.1).** The changelog explicitly records a third-party security audit with 1 HIGH, 2 MEDIUM, 1 LOW findings fixed, including prototype pollution blocking and bounded session-file reads. For a tool that reads arbitrary session files from disk, this is a non-trivial security surface — and the fact that it was audited and results documented is a structural quality signal, particularly relevant for `data_sensitivity: confidential` profiles.

- **Multi-currency support and plan tracking.** 162 ISO 4217 currency codes via the Frankfurter API, plus plan preset tracking for Claude Pro, Claude Max, Cursor Pro, and custom subscriptions. This signals intentional international and enterprise adoption targeting. The Frankfurter dependency is a network call and a potential failure point — claim to inspect whether the TUI gracefully degrades when Frankfurter is unreachable.

- **Release velocity: 25 releases in 28 days.** From v0.1.0 (2026-04-13) to v0.9.7 (2026-05-07) is 25 named releases in 28 days — roughly one release per day. Rapid iteration at this rate is a signal that issues are being surfaced and addressed quickly (e.g., the streaming dedup 6.3% token undercount fix in v0.9.6), but also that schema drift in provider data formats is an ongoing operational challenge requiring constant maintenance.

## Why clawfit should care

**1. MCP overhead as a measurable cost dimension.** codeburn's v0.9.7 MCP coverage detector is the first tool in this taxonomy to quantify the per-session token cost of loaded-but-unused MCP servers. This directly informs clawfit's L5 recommendations: a profile with many MCP servers enabled but narrow task focus may be paying significant context overhead that the clawfit scoring model cannot currently express. The tool's framing ("tool-schema overhead") maps precisely to the C (context management) component in the ETCSLV model from the Awesome-Agent-Harness survey.

**2. `codeburn optimize` output could be a clawfit recommendation input.** If codeburn's waste-pattern findings were machine-readable (they support JSON export), a clawfit integration path exists: read codeburn's session optimization output as a prior on which agent/LLM/hardware triples are actually performing well for a given user. The `codeburn yield` git-outcome correlation is especially relevant — clawfit currently has no way to distinguish agent configurations that produce committed code from those that produce abandoned sessions.

**3. The 18-provider coverage list is the most comprehensive tool inventory in this taxonomy.** codeburn's supported provider list — Claude Code, Claude Desktop, Codex, Cursor, GitHub Copilot, Gemini CLI, Kiro, OpenCode, OpenClaw, Roo Code, KiloCode, Goose, Antigravity, Oh My Pi, MiniMax, and others — is effectively a ranked inventory of what developers are actually running. Tools that have enough adoption to warrant disk-format support in a third-party observability layer are a proxy signal for market adoption weight. This list is more current than any static registry.

**4. Layer classification question: L5 vs. L2 vs. cross-cutting.** codeburn does not execute agents, does not store agent memory, and does not route tool calls. Its session data lives outside any agent's context window. This places it strictly outside L1 (no agent execution), L3 (no governance artifacts), L4 (no capability extension), and L6/L7 (no human interface or hardware). The strongest candidate layers are L5 (Memory / MCP / context layer — via the MCP usage analysis) or a cross-cutting telemetry axis not currently modeled in the taxonomy. The L5 classification is justified by the MCP surface and session telemetry, but codeburn's primary function is passive cost observability rather than memory or context management for agents — making it a boundary case worth flagging.

**5. No clawfit recommendation axis captures session-level cost observability.** clawfit's current `budget` filter operates on per-token pricing at selection time. It cannot express "this agent configuration has shown 2x cost outlier sessions in practice." codeburn's session cost data, if incorporated, would enable a `observed_cost_efficiency` dimension distinct from the nominal pricing axis.

## Preliminary interpretation

Current best reading:

- **Level 5 — Memory / MCP / context layer** (primary, with qualification). codeburn's MCP usage detector, session telemetry, and context bloat analysis operate at the same layer as MCP protocol tooling — it observes what enters context windows across sessions and identifies waste in that layer. The L5 classification is the least-wrong single-level assignment. Sub-type: **session telemetry / cost observability** — a sub-type not previously named in the taxonomy. This is structurally distinct from the memory tools (MemGPT, claude-mem, AgentDB) and MCP servers that currently anchor L5; it neither stores nor retrieves agent memory — it instruments the cost of doing both.

- **Cross-cutting telemetry axis (candidate).** The stronger architectural reading is that codeburn sits outside the 7-layer stack as a cross-cutting observability layer — analogous to how APM tools (Datadog, Honeycomb) sit outside the application stack they instrument. The 7-layer taxonomy maps tools by their role in agent execution; codeburn's role is to observe and report on that execution after the fact from on-disk artifacts. If a second cross-cutting observability tool of similar scope emerges, a dedicated observability axis (alongside the existing companion reference notes) would be more accurate than forcing L5.

- Notable: The `codeburn yield` git-outcome correlation has no analog in any current L5 tool and maps weakly to the V (evaluation interface) component in the ETCSLV model — an unmapped component in the clawfit taxonomy. This is a second instance of the V-component gap flagged in the Awesome-Agent-Harness watch entry.

## Status

- ~6k stars, v0.9.7 (2026-05-07), MIT license, TypeScript + Swift, npm/Homebrew distribution. Above the 5k observation threshold; below the level that would force an immediate registry entry decision. Primary classification L5 (session telemetry / cost observability sub-type) with a strong argument for a cross-cutting telemetry axis. Do NOT modify `docs/reference-levels.md` from this single signal. Flag for re-evaluation at 15k stars or when a second cross-vendor AI coding cost observability tool of comparable scope appears — that would satisfy the two-signal condition for naming a new sub-type or axis. Watch items: (1) verify `codeburn yield` classification accuracy against diverse git histories; (2) confirm LiteLLM pricing lag behavior during rapid model price changes; (3) track whether the MCP overhead detection methodology is adopted by other observability tools.
