# Research Watch: opencode — Open Source Terminal Coding Agent

- Repo: https://github.com/anomalyco/opencode
- Also see: https://opencode.ai/ (product site); https://opencode.ai/docs/ (official docs); https://deepwiki.com/anomalyco/opencode (architecture deep-dive); https://www.builder.io/blog/opencode-vs-claude-code (structural comparison vs Claude Code); https://github.com/different-ai/openwork (openwork — an opencode-powered alternative to Claude Cowork, secondary ecosystem signal); `docs/research-watch/2026-05-04-deepseek-tui-rust-terminal-coding-agent.md` (related: model-specialized terminal agents, same L1 layer)

## Why this is worth watching

opencode is at 157k stars (18.3k forks, 791 releases, v1.14.41 as of 2026-05-07) — making it the highest-star L1 signal in the current watch queue and likely the highest-star open-source coding agent in the entire ecosystem taxonomy. Its growth trajectory positioned it at #2 TypeScript trending (+660 stars/day at capture) despite being a mature project, indicating sustained rather than flash-mob adoption. The architectural thesis — decouple the agent runtime from both the LLM provider and the frontend surface via a client/server split — is a direct structural counter to Claude Code's proprietary, single-provider, CLI-only design, and it is backed by a working production system rather than a whitepaper or prototype.

## What stands out immediately

- **157k stars, MIT license, TypeScript-primary (62.2%), 791 releases.** Not a weekend project — 791 releases implies a cadence of roughly one release per day since inception, suggesting continuous production operation, not periodic drop-and-forget maintenance.
- **Client/server architecture with a Hono HTTP server (REST + SSE).** The agent logic lives in a server process; the TUI is one client, a mobile app is another, a Docker remote session is a third. This decoupling is structurally significant: it means opencode sessions can persist after the terminal is closed, be driven from multiple surfaces simultaneously, and be containerized without re-architecting. Claude Code has no equivalent — it is a single-process CLI where session and UI are the same binary.
- **Vercel AI SDK as the unified LLM abstraction layer.** 75+ providers (OpenAI, Anthropic, Google/Vertex, Amazon Bedrock, Azure, Groq, Together AI, Mistral, xAI, Ollama, llama.cpp, LM Studio) are supported through the same interface. The provider list is derived from Vercel AI SDK's coverage, not from custom adapters — this means opencode's provider breadth is structurally dependent on the Vercel AI SDK's maintenance rather than opencode's own engineering capacity. That is both a strength (large leveraged surface) and a risk (upstream coupling).
- **LSP integration across 20+ languages (opt-in).** The Language Server Protocol layer enables semantic analysis — type resolution, symbol navigation, dependency graph awareness — beyond what text-based grep tools provide. This is a qualitatively different capability than standard file read/write/bash tool sets: the agent can ask the LSP for "what does this symbol resolve to" rather than pattern-matching over source text. Claim to inspect: actual LSP-backed tool calls in practice vs. "the LSP is available if the agent wants to use it."
- **Two operating modes: Plan and Build.** Plan = read-only reasoning and change proposal; Build = direct code modification. The distinction maps onto the `data_sensitivity` axis clawfit already tracks — `confidential` profiles should operate in Plan mode first. This two-mode split is present in Claude Code as well, but the naming conventions and config-level defaults differ.
- **MCP integration via per-agent glob patterns.** opencode's MCP configuration is declarative (YAML/JSON glob patterns specifying which agents access which MCP tools) rather than Claude Code's session-toggle model. This is a different trust and scoping model — agents are granted MCP access at config-load time by pattern, not at runtime by operator toggle. Whether this is stronger or weaker isolation depends on use case; it is structurally different and warrants inspection before `task: code-gen` profiles involving sensitive MCP tools are recommended.
- **"OpenCode Zen" curated model list.** The team maintains a vetted list of models tested and verified by the opencode team. This is a product-level signal: opencode is building an opinionated model recommendation surface on top of the provider-agnostic runtime. That positions it closer to a recommendation layer (adjacent to what clawfit does) than a pure passthrough.
- **Anthropic OAuth block created a forcing function for direct API key usage.** Users who relied on the OAuth login flow (borrowing Claude.ai session credentials rather than paying per-token) found it broken. This is not a bug in opencode — Anthropic intentionally revoked the OAuth path. The effect: opencode + Claude now requires a paid Anthropic API key, removing the cost-arbitrage that drove some of its original user base. The tool continues to support Claude; the zero-marginal-cost Claude path is closed.
- **6.5M monthly active developer users (claimed).** This figure appears in secondary coverage and is not independently verified. Treat as claim-to-inspect. If accurate, opencode is operating at a scale comparable to major developer tools, not a niche CLI agent.

## Why clawfit should care

opencode is the canonical open-source alternative to Claude Code at L1, and at 157k stars it is structurally too large to leave unaddressed in clawfit's registry. Several concrete scoring implications:

1. **The client/server architecture breaks the `statefulness: stateless` assumption.** clawfit's current statefulness filter treats session-level persistence as a harness concern (L2+). opencode proves a L1 tool can offer persistent sessions natively via the server process. The `statefulness: session` dimension should route to opencode in profiles where session persistence is valued but a full L2 harness is unwanted overhead.

2. **75+ provider support changes the LLM preference weight dynamics.** A recommendation for opencode implicitly enables any LLM in the registry — the tool is a runtime for any model, not a fixed agent-LLM binding. clawfit's scoring currently assumes a fixed (agent, LLM) pair. Recommending opencode as the agent means the LLM column should be left open or scored separately as a second-pass decision. This is the same schema gap flagged in the Manifest signal (2026-05-05) — the effective LLM is a runtime variable, not a registry field.

3. **LSP integration is an unlocked capability not tracked in the current registry.** The `task: code-gen` profile with LSP-aware tooling is a distinct class from text-only coding. No current clawfit registry entry has an LSP capability flag. If opencode is added, a new capability axis may be warranted.

4. **The MCP glob-pattern scoping model is a distinct `data_sensitivity` signal.** Per-agent MCP access control via config-level patterns (rather than runtime toggle) implies a different operational security model for teams running opencode in enterprise contexts. The filter `data_sensitivity: confidential` currently has no sub-axis for "MCP tool access is scoped declaratively vs. dynamically."

5. **"OpenCode Zen" creates a competitive surface.** If opencode is recommending models, it is operating in the same logical space as clawfit's recommendation engine — not as a competing product, but as an intra-tool recommendation system. Understanding how Zen's model curation compares to clawfit's scoring criteria would surface either gaps or alignment signals.

## Preliminary interpretation

Current best reading:

- **Level 1 — Base runtimes / primary agent surfaces** (primary). opencode is a terminal-first, provider-agnostic coding agent runtime. The core unit of operation is an interactive coding session driven by a user in a terminal, IDE extension, or mobile app. This is the definition of L1. The client/server architecture does not elevate it to L2 — it is infrastructure serving the L1 session surface, not an orchestration layer governing multiple agents or harnesses. The persistent server process is analogous to a long-lived daemon backing a CLI tool; the agent behavior remains user-directed and single-session.
- **Level 2 — Meta wrappers / harnesses / orchestration layers** (secondary, weak). The client/server split and multi-surface support (TUI + mobile + Docker) introduce lightweight harness characteristics. If a future release adds autonomous multi-agent orchestration or programmatic session management APIs (beyond the current single-session HTTP server), L2 secondary would strengthen. Today it is weak — do not classify at L2.
- **Sub-type: provider-agnostic terminal agent with LSP-backed semantic tooling.** Distinguished from DeepSeek-TUI (L1, model-specialized, Rust) and crush (L1, Go, terminal) by the combination of: Vercel AI SDK multi-provider abstraction + native LSP integration + client/server session decoupling + 157k-star ecosystem weight. The closest comparator is aider (L1, Python, multi-model) — opencode is the TypeScript/Go-ecosystem equivalent at greater scale with LSP and client/server architecture added.
- The "OpenCode Zen" model curation layer is a proto-L4 capability (recommendation-as-feature) embedded in a L1 runtime. Not sufficient to assign a secondary L4 classification today; watch for whether Zen becomes a standalone API or grows a plugin/rating surface.

## Status

- Well above the 5k-star registry threshold (157k stars); strong candidate for L1 registry entry. Primary blocker for registry promotion: (1) confirm LSP-backed semantic tool calls are used in actual agent reasoning vs. available-but-unused; (2) confirm the 6.5M MAU figure has a verifiable source; (3) validate MCP glob-pattern scoping against `data_sensitivity: confidential` profile requirements. Schema gap flagged for calibration: the current (agent, LLM) fixed-pair scoring model cannot express opencode's "any-of-75-providers" runtime — recommend a `provider_agnostic: true` flag or a separate LLM-selection pass for tools in this class. Strong signal; flag for L1 registry intake at next calibration cycle (2026-05).
