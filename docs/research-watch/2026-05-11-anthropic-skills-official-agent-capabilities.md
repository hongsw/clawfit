# Research Watch: anthropics/skills — Anthropic's Official Agent Skills Repository and Open Standard

- Repo: https://github.com/anthropics/skills
- Also see: https://agentskills.io (open standard site + client showcase); https://agentskills.io/specification (formal spec, canonical location — `spec/agent-skills-spec.md` in the repo is a 3-line redirect); https://github.com/agentskills/agentskills (open standard governance repo on GitHub); https://anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills (engineering blog); `docs/research-watch/2026-05-06-anthropics-financial-services.md` (1st-party Anthropic domain skill pack, first L4b 1st-party entry); `docs/research-watch/2026-05-05-agency-agents-persona-skill-packs.md` (L4b community skill pack, 92.4k★)

## Why this is worth watching

anthropics/skills is the canonical reference repository for the Agent Skills open standard — a format Anthropic originated, published as an open spec at agentskills.io, and has since seen adopted by at minimum 35 named agent products (Claude Code, Cursor, OpenCode, GitHub Copilot, VS Code, Gemini CLI, OpenHands, JetBrains Junie, Letta, Goose, Roo Code, Spring AI, Snowflake Cortex Code, Databricks Genie Code, OpenAI Codex, and ~20 others). At 132k stars and 15.5k forks, this is the highest-starred entry in the L4b sub-cluster by a wide margin — approximately 1.4x the previous leader (agency-agents at 92.4k★). The combination of 1st-party provenance, an open standard with multi-vendor adoption, and a progressive-disclosure loading model (name+description at startup; full SKILL.md only when task matches) makes this the structural anchor for how capability extension is being standardized across the 2026 agent ecosystem.

## What stands out immediately

- **132k stars, Apache-2.0 / source-available (document skills), Python 84.4% / HTML 12.4%.** Verified via GitHub fetch 2026-05-11. 15.5k forks, 34 commits, 228 open issues, 597 open PRs. The commit count (34) vs. PR count (597) ratio is anomalously low — the repo functions primarily as a reference gallery and standard anchor, not as an actively iterated implementation. Most work happens in the standard governance repo (github.com/agentskills/agentskills) and in adopting agent runtimes.

- **Skill format is a SKILL.md file inside a versioned folder — minimal schema, maximum portability.** Required frontmatter fields: `name` (unique lowercase identifier) and `description` (used by the agent for activation matching). Optional: `scripts/`, `references/`, `assets/`, and any additional files. The folder is the distribution unit; no runtime binary, no SDK dependency, no registry lock-in. This is intentionally analogous to how CLAUDE.md governs agent behavior — a plain-text artifact that the consuming runtime reads.

- **Progressive disclosure loading model is the architectural core.** Skills load in three explicit stages: (1) Discovery — at startup, only `name` and `description` are loaded into the agent's awareness; (2) Activation — when a task matches the description, the full SKILL.md instructions are read into context; (3) Execution — the agent follows instructions, optionally running bundled scripts or loading referenced files. The design consequence is that an agent can maintain a large library of skills without proportional context cost at idle time. This is a meaningful architectural choice not shared by earlier L4b skill pack formats (e.g., agency-agents distributes full Markdown prompts; obsidian-skills uses a plugin system).

- **35+ named agent runtimes support the standard as of 2026-05-11.** Partial list from agentskills.io client showcase: Claude Code, Claude.ai, Cursor, OpenCode, GitHub Copilot, VS Code Copilot, JetBrains Junie, Gemini CLI, OpenAI Codex, Letta, OpenHands, Goose (Block), Roo Code, Amp, Autohand Code CLI, Factory, Mux (Coder), Spring AI, Snowflake Cortex Code, Databricks Genie Code, Laravel Boost, Firebender, Emdash, TRAE (ByteDance), nanobot, fast-agent, Mistral Vibe, Workshop, Piebald, Command Code, VT Code, Qodo, Kiro, Ona, Google AI Edge Gallery. This is the broadest multi-vendor capability-format adoption seen in this taxonomy to date — broader than MCP's initial adoption curve at comparable time post-announcement. Cross-vendor coverage includes Anthropic (Claude Code, Claude.ai), Google (Gemini CLI, Google AI Edge Gallery), Microsoft (GitHub Copilot, VS Code), OpenAI (Codex), JetBrains, Block (Goose), ByteDance (TRAE), Snowflake, Databricks, Spring (VMware/Broadcom). Claim to inspect: agentskills.io is maintained by Anthropic and adopter logos may not reflect depth of integration vs. surface endorsement.

- **Skill content categories in the repo.** Four named categories: Creative & Design (art, music, design), Development & Technical (web app testing, MCP server generation), Enterprise & Communication (branding workflows, communications), Document Skills (DOCX, PDF, PPTX, XLSX — note: document skills carry a separate source-available license, not Apache-2.0). Document skills are identified as the underlying implementation for Claude's native document editing capabilities — the first instance in this taxonomy where a skill-layer artifact is explicitly identified as powering a production first-party feature.

- **Formal spec relocated to agentskills.io/specification — the repo's spec/ directory is a redirect.** `spec/agent-skills-spec.md` contains only a 3-line redirect to the external domain. The open standard governance has been separated from the reference repo — a governance decision that signals intent to operate the format as a vendor-neutral open standard rather than as an Anthropic-owned spec. The governance repo at github.com/agentskills/agentskills is separate from the skills reference repo.

- **Install mechanisms span three deployment surfaces.** (1) Claude Code: `/plugin marketplace add anthropics/skills` then `/plugin install <skillset>@anthropic-agent-skills` — the marketplace/plugin layer is the Claude Code-native distribution mechanism. (2) Claude.ai: upload custom skills via the skills UI (paid plans). (3) Claude API: Skills API Quickstart for programmatic skill creation and invocation. The three surfaces share the same SKILL.md format but differ in delivery — plugin registry for the CLI, UI upload for the web app, API call for programmatic use.

- **Relationship to MCP is complementary, not substitutive.** One of the example skills in the Development & Technical category is MCP server generation — a skill whose purpose is to generate MCP servers. Skills extend agent behavior through instruction injection; MCP extends agent behavior through tool registration and runtime calls. The two formats can be combined: a skill can include instructions for invoking specific MCP tools, and an MCP server can expose functionality that a skill instructs the agent to use. This means the Layer 4 sub-type split (L4b skill/instruction layer vs. L4c MCP tool-use layer) is explicitly confirmed by the existence of a "how to generate MCP servers" skill inside a skill pack.

- **277k installs on a single Anthropic-published skill cited in reference-levels.md (2026-04 patterns)** as evidence that skill distribution is at app-store scale. That signal preceded this repo entry; the present entry provides the underlying standard that makes that distribution possible.

## Why clawfit should care

**1. This is the structural anchor for the L4b sub-type "1st-party model-vendor skill pack" that was previously a single-sample candidate.** anthropics/financial-services (8.5k★, `docs/research-watch/2026-05-06-anthropics-financial-services.md`) was the first 1st-party Anthropic domain skill pack; this repo is the reference implementation and open-standard origin. The sub-type is now doubly anchored at the level of both the format spec and an example domain deployment. The single-sample rule for L4b 1st-party sub-type formalisation can now be re-evaluated — the standard itself constitutes a second distinct first-party artifact.

**2. The progressive-disclosure loading model introduces a cost dimension that clawfit's skill-layer scoring does not model.** Current L4b entries (agency-agents, obsidian-skills, financial-services) are treated as static capability additions. SKILL.md's progressive disclosure means skill libraries scale sub-linearly with context cost — a library of 100 skills consumes minimal context at idle and loads individual skills only on match. This is an optimization that matters for `statefulness: long-running` profiles and for agents with large skill libraries. The `context_efficiency` property is not currently in the L4b scoring axis.

**3. Multi-vendor portability at 35+ runtimes makes Agent Skills the strongest cross-tool capability format in the current taxonomy.** OpenSpec (46.2k★, 30 tools, L3) is the comparable multi-tool signal on the governance layer; Agent Skills (132k★, 35+ runtimes) is the equivalent on the capability layer. Together they establish a pattern: the tooling ecosystem is converging on portable, vendor-neutral artifact formats at both the governance (L3) and capability (L4b) layers simultaneously. A clawfit recommendation for a team that values tool portability would want to confirm both spec-layer and capability-layer portability of their stack.

**4. Document Skills (source-available, powers Claude's native document editing) introduces a new licensing sub-type for L4b.** Most L4b entries carry MIT or Apache-2.0. The document skills subset of this repo uses a source-available license while the rest is Apache-2.0. A L4b entry where some skills are source-available and others are fully open is a new pattern. For `governance_need: hard` enterprise profiles, license granularity at the skill level is relevant and not currently expressible in the registry schema.

**5. The standard's adoption by OpenAI Codex, Google Gemini CLI, Microsoft GitHub Copilot, and VS Code creates an ecosystem interoperability signal.** Skills authored for Claude Code are nominally reusable on competing runtimes. This is directly relevant to clawfit's anti-lockin scoring axis: a team building a skill library in the Agent Skills format is not locked to Anthropic's runtime in the same way they would be if skills were stored in a proprietary format. Whether portability holds in practice (vs. in theory) is a claim to inspect — the spec at agentskills.io is the authoritative source, but runtime-specific behavioral differences could limit actual portability for instruction-heavy skills.

## Preliminary interpretation

Current best reading:

- **Level 4b — Capability / skill / plugin / tool-use layer (primary).** anthropics/skills is the reference implementation for the Agent Skills open standard — a format for packaging domain expertise and procedural workflows as portable, on-demand capability modules that agent runtimes load via progressive disclosure. The skills themselves are instruction-and-resource packs, not tool registrations (L4c) or governance files (L3), and they are consumed at runtime by the hosting agent (L1/L2). This is the canonical L4b definition: capabilities the agent has access to, delivered as portable skill artifacts.

- **Level 3 — Team harness / executable SSOT / governance layer (weak secondary).** The SKILL.md format is structurally identical to the CLAUDE.md governance file: both are plain-text artifacts injected into the agent's context to modify its behavior. The distinction is functional: CLAUDE.md governs default behavior across all tasks; SKILL.md augments behavior for specific matching tasks. The progressive-disclosure activation gate (name+description matching) is the boundary — skills are conditionally injected governance artifacts, which makes them functionally L4b (conditional capability extension) rather than L3 (always-on governance). The secondary L3 read is weak but worth noting because the format boundary between "skill that modifies behavior" and "governance file that constrains behavior" is not architecturally enforced.

- **Not L4c:** Skills are instruction/resource packs, not MCP tool registrations or function call schemas. The "MCP server generation" example skill is an instruction for how to build an MCP server, not an MCP server itself.

- **Not L2:** The repo and standard define no harness, no orchestration loop, no agent execution infrastructure. Skills are consumed by L1/L2 systems; they are not themselves L2 wrappers.

- Notable subcategory: the document skills subset (DOCX, PDF, PPTX, XLSX) powers first-party Claude document features — making this the first L4b entry where skill artifacts directly underlie a production first-party capability rather than purely extending a third-party runtime. This is an architectural signal about how Anthropic intends to use its own skill format internally.
