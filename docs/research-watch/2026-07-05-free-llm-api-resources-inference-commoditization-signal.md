# Research Watch: free-llm-api-resources — Inference Access as Infrastructure Knowledge

- Repo: https://github.com/cheahjs/free-llm-api-resources (⭐25,352)
- Source: GitHub Trending Python daily, July 5 2026

## Why this is worth watching

At 25,352 stars with +510 in a single day, this repository sits above Aider (~22k stars), a full-featured production-grade coding agent with a multi-year development history — and this repo is a curated reference list. That inversion is the signal: practitioners are treating "which providers give free LLM inference access, and at what rate limits" as infrastructure-level knowledge worth bookmarking at higher rates than they bookmark agent frameworks. The daily velocity (+510) is not a one-time spike — commit history shows weekly-to-biweekly "Update README with latest models" automated commits and ongoing provider additions, indicating sustained operational relevance rather than a viral moment. The list is hybrid-generated: a Python script (`src/pull_available_models.py`) polls provider APIs directly (Groq, OpenRouter, Google AI Studio via Cloud Quotas API, Cloudflare, GitHub Models, Lambda Labs, SambaNova, Scaleway, Cohere, Chutes, Kluster, Hyperbolic, OVH) while a subset of providers (NVIDIA NIM, Mistral, HuggingFace, Vercel AI Gateway, OpenCode Zen, Cerebras) remain hardcoded — which means the "automated" characterization in the README header is partially accurate and partially aspirational.

## What stands out immediately

- **README is code-generated, not hand-maintained:** The file opens with "WARNING: DO NOT EDIT THIS FILE DIRECTLY. IT IS GENERATED BY src/pull_available_models.py" — this is not a bookmark list updated by hand; it is a document artifact from a pipeline. The pipeline queries provider API endpoints for live model availability, then writes a markdown file. The implication is that the data is machine-readable at source even though the output format is markdown.

- **Free tier coverage is broader than commonly assumed:** At least 14 providers are tracked in the free tier (no credit card required), including major inference endpoints: OpenRouter, Google AI Studio, NVIDIA NIM, Mistral (two separate endpoints — La Plateforme and Codestral), HuggingFace Inference, Vercel AI Gateway, OpenCode Zen, Cerebras, Groq, Cohere, GitHub Models, Cloudflare Workers AI, OVH, Chutes, Kluster. A second tier of ~13 providers offers trial credits ranging from $0.50 (Novita) to $1M tokens (Alibaba Cloud, Scaleway).

- **Rate limit granularity is per-model, not per-provider:** The tracked metadata goes below provider level to per-model rate limit rows. Example data confirmed: Groq Llama 3.3 70B — 1,000 requests/day, 12,000 tokens/minute; Google AI Studio Gemini 3.5 Flash — 250,000 tokens/minute, 20 requests/day, 5 requests/minute; OpenRouter — 20 requests/minute, 50 requests/day baseline (expandable to 1,000/day with $10 topup). This granularity is operationally useful for pipeline scheduling; it is not present in most LLM benchmark comparisons.

- **The same open-weight model appears across multiple simultaneous free providers:** Llama 3.3 70B is available free on Groq, Cloudflare Workers AI, OVH, and Chutes simultaneously; GPT-OSS variants (120B, 20B) appear across multiple providers; Gemini 3.5/3/2.5 Flash variants are available via Google AI Studio with distinct per-model rate limit rows. This multi-homing pattern — one model, many free endpoints — is a structural feature the list makes visible that individual provider pages do not.

- **Editorial scope is explicitly defined:** The repo explicitly excludes "services that are not legitimate (eg reverse engineers an existing chatbot)" — a direct reference to services like unofficial OpenAI proxies and jailbroken API wrappers. This scoping decision distinguishes the list from informal "free GPT" link compilations and gives it credibility as a practitioner reference for production-adjacent use.

- **Context window sizes and per-entry timestamps are absent:** Rate limit metadata is tracked; context window sizes per free-tier model are not confirmed in the visible data structure. No per-entry last-updated timestamps exist — meaning the data freshness for hardcoded entries (NVIDIA NIM, Mistral, HuggingFace, Vercel AI Gateway, OpenCode Zen, Cerebras) is unknown and cannot be distinguished from stale entries without consulting those providers directly.

- **Automation is partial, not comprehensive:** The `pull_available_models.py` script queries 13 providers via their APIs. The remaining providers in the list (NVIDIA NIM, Mistral, HuggingFace, Vercel AI Gateway, OpenCode Zen, Cerebras) are hardcoded in the script, meaning rate limit updates for those providers require manual code changes rather than automated refreshes. The README's implied status as a fully automated document is inaccurate for roughly 40% of its free-tier entries.

- **No tooling layer built on top of it (confirmed):** The repo does not ship an SDK, API, or structured data file (e.g., JSON) alongside the markdown. Use cases — eval pipelines, cost routing, CI/CD cost guards — would need to parse the markdown or build their own pipeline from the Python source. The 421 commits and 32 pull requests indicate active community participation, but all contributions are to the reference data, not to tooling built on top of it.

## Why clawfit should care

**The cost scoring dimension is underspecified for zero-cost profiles.** clawfit's scoring weights cost at 0.25 and uses a `budget` filter to eliminate LLMs above a threshold. The current `llms.json` registry does not distinguish between "free tier available" and "commercial API required" for a given model, and does not track rate limit constraints that govern whether a free tier is viable for a given workload. A `budget: 0.00` profile today returns whatever LLM entries have cost near zero in the registry; it does not know that Llama 3.3 70B is simultaneously available at 1,000 req/day on Groq and at different limits on Cloudflare, OVH, and Chutes.

**Rate limits are a throughput constraint that clawfit's latency axis does not model.** A free API endpoint at 5 requests/minute and 20 requests/day is not equivalent to a paid endpoint for any workload that exceeds those limits, but both would receive the same `latency: medium` score in the current model. The distinction matters for eval pipelines (high volume, low budget) and for single-user dev tooling (low volume, high cost sensitivity) differently. The existing scoring does not have a `throughput_budget` or `rate_limit_sensitivity` field to separate these cases.

**The list is a potential data source for `llms.json` free-tier annotation.** If clawfit were to add a `free_tier` boolean and `rate_limit_rpm` / `rate_limit_rpd` fields to LLM registry entries, `pull_available_models.py` (or its output) is the most current machine-readable source for populating those fields for providers it polls via API. This is an opportunity, not a requirement; it would require parsing the markdown output or forking the upstream Python script.

**The multi-homing pattern signals a new registry modeling question.** When Llama 3.3 70B is available free across four providers simultaneously, the "llm" entry in a (agent, llm, hardware) triple is partially decoupled from a single cost value. The model is not one cost point; it is a set of (provider, rate_limit, cost) tuples. clawfit's current flat LLM registry has no mechanism to express that the same base model resolves to different cost and throughput profiles depending on which inference endpoint is used. This is a schema question, not a data quality question.

## Preliminary interpretation

Current best reading:

- **Level 7 — Infrastructure / hardware / edge layer** (primary): this repo catalogs LLM inference access points — API endpoints, provider tiers, and rate limits — which is the economic surface of inference infrastructure. The closest structural analogue in clawfit's existing taxonomy is `hardware.json`, which tracks compute substrate options; this list tracks compute access options at the API layer.

- **Not a deployable tool; no registry entry warranted.** This is a reference artifact — a maintained data document about infrastructure, not a framework, runtime, SDK, or agent. It belongs in the research watch log, not the agent or LLM registry. The Python generation pipeline is interesting but is not itself a tool practitioners deploy.

- **Meta-signal about LLM commoditization, not just a list.** The star count relative to active agent frameworks is the primary analytical observation. When a reference list that answers "where can I get LLM inference for free" accumulates more stars than most agent frameworks, it is evidence that inference cost is a primary decision variable for a large share of the practitioner community — and that the market has fragmented enough providers and free tiers that the answer is non-obvious. This is a commoditization signal: inference is approaching a state where access (which providers, what rate limits) matters more than capability differentiation (which model).

- **Scope boundary note:** `docs/reference-levels.md` currently excludes "full standalone LLM model catalogs, general cloud infrastructure" from its scope. This repo is not a model catalog (it does not compare model quality or benchmark scores); it is a rate-limit and access-tier catalog for inference infrastructure. The distinction is meaningful: it falls within scope as an infrastructure reference, not outside scope as a model catalog.

## Claims to verify

- **Automation schedule:** Whether `pull_available_models.py` runs on a GitHub Actions cron schedule (daily/weekly) or is triggered manually is not visible from the repo surface. The automated commit pattern ("Update README with latest models") suggests scheduled execution, but the Actions configuration file was not confirmed in the available content.

- **Rate limit accuracy for hardcoded providers:** NVIDIA NIM, Mistral, HuggingFace, Vercel AI Gateway, OpenCode Zen, and Cerebras are hardcoded in the generation script rather than API-polled. Their rate limit entries reflect the state at the time of the last manual code update, not the current provider configuration. Staleness cannot be assessed without direct provider verification.

- **Context window coverage:** The visible rate limit tables do not include context window sizes per model. Whether `data.py` stores context window metadata alongside model name mappings is unconfirmed; if absent, the list does not serve as a complete LLM capability reference.

- **Geographic restrictions:** Whether free tier access is restricted by provider geography (e.g., US-only, EU-only) is not tracked in the visible metadata. A `budget: 0.00` profile recommendation based on this list could be non-viable for users outside supported regions.

- **Frontier model coverage:** Whether commercial-API-only frontier models (Claude, GPT-4o, Gemini 1.5 Pro) appear in any free tier is unconfirmed from the visible data. The confirmed models (Llama 3.3 70B, GPT-OSS 120B/20B, Gemini 3.5 Flash) are open-weight or lite-tier models. The "free frontier model" claim is only validated for Flash-tier and open-weight models, not full-capability frontier APIs.
