## Why this is worth watching

dotnet/skills is the first 1st-party **stack-specific** skill pack shipped by a major platform owner who is *not* a model vendor. Anthropic published anthropics/skills (the reference implementation of the agentskills.io standard) and anthropics/financial-services (a domain skill pack); both are model-vendor-published. Microsoft's entry is structurally different: it is the **platform-stack vendor** (the company that ships .NET itself) publishing skills that teach AI coding agents how to use *their* runtime, SDK, and ecosystem. At 2,739 stars on 2026-05-24 with +266 daily (GitHub Trending Daily #7), the absolute count is well below anthropics/skills (132k★) but the provenance class is new: a programming-language-platform owner adopting the Anthropic-originated open standard as a distribution channel for first-party developer guidance. Combined with the parent microsoft/skills repo (174 skills across 6 languages and Azure/Foundry), this is the strongest 2026 signal yet that the L4b skill-pack pattern is being institutionally adopted by platform vendors rather than only model vendors and community curators.

## What stands out immediately

- **MIT-licensed, C# 97.0%, launched 2026-03-09, v1.0.0 tagged 2026-04-21.** Approximately ten weeks from launch to v1.0.0 — fast versioning for a content repository, suggesting the team treats the skill pack as a release artifact with stability commitments rather than a continuously mutating gallery. The MIT license is more permissive than anthropics/skills' split licensing (Apache-2.0 core + source-available document skills), which matters for downstream redistribution.
- **11 plugins shipped, all stack-scoped.** `dotnet` (core), `dotnet-data` (Entity Framework), `dotnet-diag` (performance debugging and incident analysis), `dotnet-msbuild` (build optimization), `dotnet-nuget` (package management), `dotnet-upgrade` (framework migration), `dotnet-maui` (mobile dev), `dotnet-ai` (LLM integration, RAG, agentic workflows, ML.NET), `dotnet-template-engine` (scaffolding), `dotnet-test` (test execution and diagnostics), `dotnet-aspnet` (web). Plus a `dotnet11` plugin for net-new APIs in .NET 11. Every plugin is anchored to a specific subsystem of the .NET stack — this is not a general-purpose coding skill pack with a `dotnet/` folder, it is the .NET team's institutional knowledge encoded as agent-consumable artifacts.
- **Follows the agentskills.io spec — SKILL.md frontmatter plus plugin.json bundling.** No custom format. The launch blog post explicitly cites agentskills.io as the standard being followed. This is direct first-party evidence (Microsoft platform team → Anthropic-originated standard) that the open standard has crossed from "model-vendor adoption" into "platform-vendor adoption" — a different and arguably stronger validation than runtime adoption by competing model vendors. Microsoft is simultaneously a runtime consumer (GitHub Copilot, VS Code) and now a content publisher in the same format.
- **Runtime targets span Microsoft and competitors.** Installable into Copilot CLI, VS Code / VS Code Insiders (preview, via marketplace URL added to the Copilot extension), Visual Studio 2026 (via the .github + MCP extension), Claude Code (`/plugin marketplace add dotnet/skills`), Cursor, and OpenAI Codex CLI. Microsoft is publishing content that runs in Anthropic's and OpenAI's runtimes — a substantively different posture from the historical Microsoft pattern of platform-exclusive developer tooling. The skill pack is portable by virtue of being SKILL.md, and Microsoft is choosing to lean into that portability rather than fork the format.
- **Evaluation dashboard with measured baselines.** dotnet.github.io/skills hosts a Copilot quality scorecard tracked across the last 50 evaluation runs (summary cards) and 14 days (charts), measuring task performance with vs. without the skill plugin loaded. The launch announcement emphasizes that each merged skill undergoes "lightweight evaluation scoring against baselines to verify actual improvement before shipping." This is the first L4b entry in the watch corpus with an explicit pre-merge evaluation gate published as a live dashboard — a meaningful quality-engineering signal that distinguishes a platform-vendor-curated skill pack from community aggregators where the merge bar is curatorial.
- **microsoft/skills (parent repo, 174 skills) frames the broader strategy.** dotnet/skills sits inside a larger Microsoft initiative covering Python (39), .NET (29 — note count differs from dotnet/skills' 11 plugins; microsoft/skills appears to count individual skills, dotnet/skills counts plugin bundles), TypeScript (25), Java (26), Rust (7), Foundry/AI services (11), and core infrastructure (10), plus MCP servers and custom agent personas. dotnet/skills is the stack-specific subset that the .NET team owns directly; microsoft/skills is the umbrella. This dual-repo pattern (umbrella + stack-team-owned slice) is a governance choice worth noting — distinct from Anthropic's monorepo approach.
- **SDK integration in flight.** Issue dotnet/sdk#54243 proposes exposing dotnet/skills plugins via a native `dotnet skill` command in the .NET SDK itself. If accepted, this would make the skill pack discoverable and installable from the same CLI that .NET developers already use to manage projects, packages, and tools — a different distribution channel than the current marketplace/plugin model. Claim to inspect: the issue exists but is not yet implemented; whether the .NET SDK absorbs skill management as a first-class concept is the validating signal.
- **At least three .NET skill packs exist in parallel.** dotnet/skills (Microsoft official, 2,739★), davidfowl/dotnet-skillz (David Fowler, Microsoft principal architect for ASP.NET — community-framed but high-credibility), and managedcode/dotnet-skills (third-party CLI-installable catalog targeting Codex/Claude Code/Copilot/Gemini). The official pack is not the only one — the .NET ecosystem already has a small sub-cluster of skill packs, similar to how Claude Code accumulated multiple curators (Anthropic, Vercel, Composio, VoltAgent, mattpocock) within months of the format's release.

## Why clawfit should care

**1. New L4b provenance class: platform-stack vendor (not model vendor).** Existing L4b 1st-party entries are model-vendor-published (anthropics/skills, anthropics/financial-services) or platform-vendor-published from web-infra companies (browserbase/skills). dotnet/skills is the first from a programming-language-platform owner. This provenance class matters because the skills encode platform-team knowledge that no community curator could replicate at the same authority level — `dotnet-upgrade` is authored by the team that ships the upgrade tooling, `dotnet-diag` by the team that ships the diagnostic surface. For clawfit recommendations that filter on `governance_need: hard` or `task: code-gen` against a specific stack, first-party stack-vendor skill packs are a different recommendation class than community packs of equivalent scope.

**2. Stack-anchored scoring is not currently a clawfit axis.** L4b entries are scored along domain (coding, design, knowledge work, finance, legal), curator type (1st-party, community, aggregator), and runtime compatibility. The .NET pack introduces a `stack: dotnet` filter dimension that the current scoring does not express. For a recommendation where the user profile includes a primary language/stack, a stack-matched first-party skill pack is materially more relevant than a stack-agnostic skill pack. The signal here is structural: if Java, Go, Rust, Python platform teams follow Microsoft's lead (microsoft/skills already covers them as a single umbrella, but no equivalent independent first-party Java/Go/Rust skill pack from the language owner exists yet as of this writing), the stack dimension becomes a first-class L4b axis.

**3. Microsoft's dual posture (runtime + content publisher in the same open format) is the cross-vendor portability validation Agent Skills needed.** The 2026-05-11 anthropics/skills watch noted 35+ runtimes adopting the format as consumers. dotnet/skills demonstrates the inverse direction: Microsoft, owner of two major runtime surfaces (Copilot, VS Code), publishing content into the standard rather than forking a Microsoft-specific format. This is the first major-vendor evidence that the format is being treated as a neutral substrate rather than an Anthropic asset. For clawfit's `vendor_lock_in` scoring axis, this strengthens the case that skill libraries authored in SKILL.md are durable across runtime changes.

**4. Live evaluation dashboard sets a quality-engineering benchmark for L4b entries.** Most tracked L4b skill packs ship without published evaluation. dotnet.github.io/skills publishes Copilot quality deltas with and without the skill plugin loaded, across rolling windows. If this becomes a norm for first-party skill packs, the clawfit recommendation pipeline could eventually consume measured task-quality lift as a scoring input rather than relying on star count and provenance proxies. Worth tracking whether other first-party packs (anthropics/financial-services, browserbase/skills) adopt comparable measurement surfaces.

**5. Below registry threshold today, but velocity and provenance argue for early tracking.** 2,739 stars is well under the standard 5k registry inclusion bar. The signal here is not raw popularity — it is the structural addition of a new provenance class (platform-stack vendor) and a new scoring dimension (stack anchoring). The recommendation is research-watch tracking now, with promotion criteria: (a) star count crosses 5k, (b) the dotnet/sdk#54243 native `dotnet skill` integration ships, or (c) a second major language-platform vendor (Java/Go/Rust/Python) publishes an equivalent first-party stack-specific skill pack within the same quarter.

## Claim to inspect vs. validated facts

- **Validated (from repo, GitHub Trending #7 listing, and Microsoft devblog):** MIT license, 2,739 stars at 2026-05-24, +266 daily, 11 plugins shipped, launched 2026-03-09, v1.0.0 on 2026-04-21, C# 97.0%, follows agentskills.io spec with SKILL.md + plugin.json, supports Copilot CLI / VS Code (Insiders) / Visual Studio 2026 / Claude Code / Cursor / Codex CLI, microsoft/skills parent repo exists with 174 skills across 6 languages, dotnet.github.io/skills evaluation dashboard exists.
- **Claim to inspect:** Whether the evaluation methodology on dotnet.github.io/skills is statistically sound or marketing-grade — only the high-level framing has been read, not the underlying benchmark dataset. Whether `/plugin marketplace add dotnet/skills` in Claude Code provides parity with the native VS Code/Copilot experience or is a fallback. Whether dotnet/sdk#54243 (native `dotnet skill` command) lands in a .NET SDK release. Whether the 11-plugin count in dotnet/skills versus the 29 .NET skills counted in microsoft/skills indicates duplicate authoring, different counting granularity (plugin vs. individual skill), or two parallel publishing tracks. Whether the parallel community pack davidfowl/dotnet-skillz is an unofficial preview or an intentional second source.

## Preliminary interpretation

Current best reading:

- **Level 4b — Capability / skill / plugin / tool-use layer (primary).** dotnet/skills is a stack-specific skill pack following the agentskills.io open standard, packaged for consumption by multiple agent runtimes. Direct match for the canonical L4b definition: a capability extension delivered as portable SKILL.md artifacts that runtimes load on demand.

- **New L4b sub-type: "1st-party platform-stack-vendor skill pack."** Distinct from existing sub-types (1st-party model-vendor: anthropics/skills, anthropics/financial-services; 1st-party infrastructure-vendor: browserbase/skills; community aggregator: VoltAgent, mattpocock, Composio; platform-deployment-vendor: Vercel skills CLI). The defining characteristic is that the publisher owns the platform stack that the skills teach the agent to use — the skill content is authoritative because the publisher controls the underlying runtime/SDK/tooling.

- **Cross-cutting signal — not yet strong enough to mutate `docs/reference-levels.md`.** The new sub-type is currently a single-sample observation (dotnet/skills as the only L4b entry from a programming-language-platform owner; davidfowl/dotnet-skillz is adjacent but personal-branded, not Microsoft-owned-and-published; microsoft/skills is umbrella, not stack-team-owned). Per protocol, no taxonomy change made. Flag for ecosystem-mapper consideration if a second language-platform vendor (Oracle/Java, Google/Go, Rust Foundation, Python Software Foundation, or equivalent) publishes a comparable first-party stack-specific skill pack within the next 60 days.

- **Not L3:** dotnet/skills does not define a team harness, governance file format, or executable SSOT. It is consumed by L1/L2 runtimes, not a wrapper or orchestration layer over them.

- **Not L4c:** Skills are instruction packs, not MCP tool registrations or function-call schemas. The `dotnet-msbuild` and `dotnet-diag` skills instruct the agent on how to use existing build/diagnostic tooling rather than registering new tool-call surfaces.
