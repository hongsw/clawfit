# Research Watch: Anthropic-Cybersecurity-Skills — Community Domain Skill Pack for Cybersecurity

- Repo: https://github.com/mukul975/Anthropic-Cybersecurity-Skills
- Also see: https://github.com/anthropics/skills (canonical Agent Skills reference + open standard, 132k★); https://agentskills.io (open standard site + spec); `docs/research-watch/2026-05-11-anthropic-skills-official-agent-capabilities.md` (anthropics/skills, 1st-party reference implementation); `docs/research-watch/2026-05-06-anthropics-financial-services.md` (1st-party vertical skill pack); `docs/research-watch/2026-05-05-agency-agents-persona-skill-packs.md` (community cross-domain pack, 92.4k★); `docs/research-watch/2026-03-31-labclaw-biomedical-skill-library.md` (biomedical vertical skill library); `docs/research-watch/2026-04-07-shannon-autonomous-ai-pentester.md` and `docs/research-watch/2026-04-12-strix-autonomous-security-testing-platform.md` (L1 security-domain agents)

## Why this is worth watching

This is the first **community-authored vertical skill pack** in the taxonomy that explicitly conforms to the Agent Skills open standard (agentskills.io) and targets a single high-stakes domain (cybersecurity) at production-grade scale. At 754 skills mapped against five industry frameworks (MITRE ATT&CK v18, NIST CSF 2.0, MITRE ATLAS v5.4, MITRE D3FEND v1.3, NIST AI RMF 1.0), it is the largest single-domain skill pack tracked to date — denser than anthropics/financial-services (50+ skills across 7 verticals) and on a different axis than agency-agents (144 cross-domain personas). The name choice ("Anthropic-Cybersecurity-Skills") is itself a signal: the community is using the model vendor's brand as a format identifier, even while explicitly disclaiming affiliation. Velocity is real (+281 stars in one day, GitHub Trending Daily #9 on 2026-05-24) but the structural interest is larger than the day-over-day delta.

## What stands out immediately

- **7,390 stars, 1k forks, Apache-2.0, Python 99.6% / PowerShell 0.4%.** Verified via WebFetch 2026-05-24. Latest tagged release v1.2.0 (2026-04-06); v1.0.0 (2026-03-11) shipped 734 skills, current main branch contains 754. Author: Mahipal Jangra (@mukul975), single-maintainer community project. **Above the 5k-star registry-watch threshold.**

- **754 skills across 26 security domains.** Largest domain clusters: Cloud Security (60), Threat Hunting (55), Threat Intelligence (50), Web Application Security (42), Network Security (40). Smallest: Deception Technology (2), Compliance & Governance (5). Full domain list: Cloud Security, Threat Hunting, Threat Intelligence, Web Application Security, Network Security, Malware Analysis, Digital Forensics, Security Operations, Identity & Access Management, SOC Operations, Container Security, OT/ICS Security, API Security, Vulnerability Management, Incident Response, Red Teaming, Penetration Testing, Endpoint Security, DevSecOps, Phishing Defense, Cryptography, Zero Trust Architecture, Mobile Security, Ransomware Defense, Compliance & Governance, Deception Technology. Counts are claim-to-inspect (README assertion, not independently audited).

- **Five-framework cross-mapping is the load-bearing differentiator.** Each SKILL.md frontmatter carries explicit framework references: `atlas_techniques`, `d3fend_techniques`, `nist_ai_rmf`, `nist_csf`. Frameworks covered:
  - MITRE ATT&CK v18 — 14 tactics, 200+ techniques (offensive TTPs)
  - NIST CSF 2.0 — 6 functions, 22 categories (governance)
  - MITRE ATLAS v5.4 — 16 tactics, 84 AI/ML-specific techniques (AI threats)
  - MITRE D3FEND v1.3 — 267 defensive countermeasures
  - NIST AI RMF 1.0 — 4 functions, 72 subcategories (AI risk management)
  
  The simultaneous coverage of both classical security (ATT&CK, CSF, D3FEND) and AI-specific threat frameworks (ATLAS, AI RMF) is unusual — most security tooling tracks one or the other. Claim to inspect: whether the framework-to-skill mappings are accurate at scale (754 × 5 frameworks = thousands of mapping assertions; single maintainer; no third-party audit cited).

- **File layout follows the agentskills.io specification exactly.** `skills/[skill-name]/SKILL.md` with YAML frontmatter (`name`, `description`, `domain`, `subdomain`, `tags`, framework technique IDs, `version`, `author`, `license`) + Markdown sections (When to Use, Prerequisites, Workflow, Verification) + optional `references/`, `scripts/`, `assets/` directories. This is the canonical Agent Skills layout — the same shape used by anthropics/skills. The pack is a conformance test of the open standard at scale by a non-Anthropic author.

- **Installation uses the agentskills.io `npx skills add` convention.** `npx skills add mukul975/Anthropic-Cybersecurity-Skills` is the documented primary install path; `git clone` is the secondary path. The `npx skills` CLI is the open-standard install client (not an Anthropic-controlled distribution channel). README claims compatibility with Claude Code, GitHub Copilot, Cursor, Gemini CLI, OpenAI Codex CLI, LangChain, CrewAI, AutoGen, Devin, SWE-agent — "any agentskills.io-compatible platform." Claim to inspect: whether installation correctly populates skill directories in each named runtime, and whether the framework-id frontmatter survives the install conversion for runtimes that re-parse skill metadata.

- **Disclaimer about Anthropic affiliation is explicit and prominent.** README opens with: "⚠️ **Community Project** — This is an independent, community-created project. Not affiliated with Anthropic PBC." Same disclaimer repeats in the footer. The repo name retains "Anthropic" as a format/standard identifier — a brand-as-format-identifier pattern that the Agent Skills standard does not address. (Compare: nobody names a repo "Microsoft-VSCode-Extensions" to indicate VSCode extension format conformance.) This naming convention is a single-instance signal; flag if a second community vertical pack ("Anthropic-Healthcare-Skills", "Anthropic-Legal-Skills") appears.

- **Progressive disclosure architecture is preserved.** README quotes ~30 tokens to scan a single skill's frontmatter, 500–2,000 tokens for the full workflow body. This matches the architectural property documented for anthropics/skills (`2026-05-11-anthropic-skills-official-agent-capabilities.md`): a library of 754 skills consumes minimal context at idle and loads individual skills only on task match. At this skill count, progressive disclosure is no longer an optimization — it is the only loading model that makes the library usable. A naïve always-loaded model would consume hundreds of thousands of tokens before any task.

- **MITRE ATT&CK Navigator layer shipped in releases.** Beyond raw skill files, releases bundle an ATT&CK Navigator JSON layer — the standard format for visualizing technique coverage. This is the first L4b skill pack in the taxonomy to ship a domain-standard visualization artifact alongside the skills themselves. Indicates the maintainer is thinking about the pack as a coverage map, not just a collection.

- **No MCP integration documented in the pack itself.** Unlike anthropics/financial-services (which embeds `.mcp.json` manifests for 11 named data providers), this pack does not bundle MCP server configurations for security tools (no embedded references to Splunk, CrowdStrike, Wazuh, ELK, Suricata, Volatility, YARA infrastructure). Skills are pure instruction-and-workflow artifacts. This keeps it cleanly in L4b without an L4c surface, but it also limits operational realism — a SOC analyst skill that does not connect to a SIEM is a checklist, not an executable workflow.

- **GARS-2026 academic survey integration cited; Casky.ai playground referenced.** Both are external integrations described in the README. Claim to inspect — neither verified independently. The academic-survey integration is unusual provenance for a community skill pack; most community packs cite no academic anchoring.

## Why clawfit should care

**1. This is the first community implementation of the Agent Skills open standard at vertical-domain scale.** anthropics/skills (132k★) is the reference implementation by the format author; anthropics/financial-services (8.5k★) is the 1st-party domain pack; agency-agents (92.4k★) is cross-domain community but predates the formal Agent Skills standard adoption pattern. This pack occupies the (community-authored) × (single-vertical-domain) × (agentskills.io-conformant) cell that was previously empty. It tests whether the open standard can sustain third-party vertical pack development without 1st-party gravity — an interoperability test that matters for clawfit's anti-lockin scoring axis.

**2. It is the third high-signal entry in the security-domain cluster, alongside two L1 agents.** Shannon (36k★, autonomous AI pentester, `2026-04-07-shannon-autonomous-ai-pentester.md`) and Strix (`2026-04-12-strix-autonomous-security-testing-platform.md`) are L1 domain-specialized agents for security testing. This pack is the L4b capability layer for the same domain. The security/pentest cluster — flagged in `reference-levels.md` 2026-04 patterns ("Domain-specialized security agents emerging") — now has signals at two layers (L1 + L4b) and references the `security-testing` task-type gap that reference-levels.md already noted. The cluster-formation criterion (≥3 layers with ≥1 entry at ~25k★) is **not yet met** — current cluster is L1 (Shannon 36k★, Strix) + L4b (this pack 7.4k★), no L2/L3 signal. Flag for monitoring; do not promote to cluster status today.

**3. Domain-specific skill aggregator is a sub-type pattern, not a one-off.** LabClaw (240 biomedical skills, 2026-03-31), this pack (754 cybersecurity skills, 2026-05-24), and anthropics/financial-services (50+ financial skills, 2026-05-06) form a three-sample pattern: **single-domain skill aggregator** (vs. agency-agents' multi-domain cross-vertical pack, vs. anthropics/skills' format reference). The provenance varies (community / community / 1st-party), the domain varies (biomedical / cybersecurity / financial), the format conformance varies (LabClaw predates agentskills.io; this pack is conformant; financial-services is 1st-party conformant). The shared structural property is **single-vertical-domain dense skill aggregation** as a distinct packaging strategy. clawfit's ecosystem-mapper should evaluate whether this warrants explicit naming under L4b alongside the existing "1st-party model-vendor skill pack" sub-type. Per task brief, no `reference-levels.md` modification today — flagged as accumulating signal.

**4. Framework-mapped skills introduce a `governance_traceability` dimension absent from current L4b scoring.** Skills with explicit MITRE/NIST technique IDs in frontmatter are auditable in a way that prose-only skills are not — a SOC team can answer "what coverage do we have for T1078 (Valid Accounts)?" by querying frontmatter. For `governance_need: hard` profiles (regulated industries, SOC2/ISO compliance), this traceability is registry-relevant. The clawfit registry schema does not currently express skill-level framework mapping; this pack is evidence that the dimension exists in the wild and matters for at least one domain (security). Compliance-domain skill packs (when they appear) would likely carry similar `nist_csf`/`iso27001` frontmatter.

**5. The `Anthropic-` brand-as-format-identifier naming convention is a weak governance signal.** The community is treating "Anthropic" as a synonym for the Agent Skills format — even while the open standard has been deliberately separated from the Anthropic org (governance moved to github.com/agentskills/agentskills, spec hosted at agentskills.io). If this naming pattern spreads, it risks blurring the open-standard positioning Anthropic is trying to establish. This is not a clawfit scoring issue but is an ecosystem-positioning observation worth recording.

## Preliminary interpretation

Current best reading:

- **Level 4b — Capability / skill / plugin / tool-use layer (primary).** Vertical-domain skill aggregation conforming to the Agent Skills open standard; 754 SKILL.md artifacts with YAML frontmatter, Markdown workflow bodies, and standard install path via `npx skills add`. Sits cleanly in the existing L4b "Domain skill packs" sub-cluster alongside agency-agents, anthropics/financial-services, obsidian-skills, caveman, marketingskills, LabClaw. Differentiator within L4b: largest single-domain skill count tracked; first community-authored agentskills.io-conformant vertical pack; explicit five-framework cross-mapping in frontmatter.

- **Not L1:** This is not an agent runtime. It contains no execution loop, no model invocation, no agent process. Distinct from Shannon and Strix (which are L1 security-domain agents) — those run, this is loaded.

- **Not L4c:** No MCP server definitions, no tool-call schemas, no runtime function registrations. Pure instruction artifacts. Distinct from MCP-based security tooling.

- **Not L3:** No governance workflow, no sprint contracts, no approval chains, no orchestration scripts. The ATT&CK Navigator layer is a visualization artifact, not a governance mechanism.

Notable sub-type signal (do not modify reference-levels.md per task brief):

- **Single-vertical-domain skill aggregator** is now a three-sample pattern within L4b: LabClaw (biomedical, 240 skills), this pack (cybersecurity, 754 skills), anthropics/financial-services (financial, 50+ skills). Distinct from cross-domain persona packs (agency-agents) and from format-reference packs (anthropics/skills). The candidate sub-type would sit alongside the existing "1st-party model-vendor skill pack" sub-type formalised 2026-05-11 — the two are orthogonal dimensions (provenance × domain-scope). Ecosystem-mapper to evaluate at next scan cycle.

- **Framework-traceable skill pack** is a single-sample sub-property within L4b: skills with explicit external-framework technique IDs in frontmatter, enabling auditable coverage queries. Single instance; do not name.

## Status

- **Watching, registry-eligible deferred.** 7,390★ exceeds the 5k registry-watch threshold. Single-maintainer community provenance + claim-heavy README (754 skills, 5 frameworks, 26 platforms — all maintainer assertions) argue for hold pending independent verification on at least one of: (a) the install path actually populates Claude Code skill directories correctly via `npx skills add`, (b) the MITRE ATT&CK technique mappings are accurate at sample scale (audit 10 random skills against ATT&CK Navigator), (c) the AI-specific framework coverage (ATLAS, AI RMF) is non-trivial rather than mechanically labeled. The pack is a strong candidate for L4b registry inclusion if any one of these verifications lands.
