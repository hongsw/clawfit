# Research Watch: Anthropic Fermat's Last Theorem — P2M Multi-Agent Proof at Research Scale

- Repo: https://github.com/anthropics/fermats-last-theorem (⭐641)
- Source: Hacker News (707 points, 2026-09-05); GeekNews (4 points, 2026-09-05)
- Also: https://www.anthropic.com/research/formalizing-fermats-last-theorem

## Why this is worth watching

Anthropic published a complete, machine-verified formalization of Fermat's Last Theorem in Lean 4. The proof comprises 29,511 intermediate theorems, 13 million lines of Lean code, and was generated by a multi-agent Claude harness (labeled P2M — Prove2Me internally) over 11 days consuming ~6 billion output tokens.

This is not a benchmark result or a demo. The Lean kernel provides an external correctness oracle — either the proof compiles under the three standard Lean axioms or it does not. It did. The proof was independently verified by three systems: the Lean kernel itself, the `comparator` tool (kernel replay), and `nanoda` (an independent Rust-based Lean kernel). The achievement is checkable by anyone with the repo and ~67 GB of disk space.

The relevance to the AI agent ecosystem is architectural, not mathematical: a multi-agent harness coordinating 30k parallel and sequential subtasks across 11 days, governed by a dependency DAG that prevented redundant work and tracked cross-agent citations, is a new existence proof for what L2/L3 systems can do.

## What stands out immediately

- **Scale**: 29,511 intermediate theorems proved; 13 million lines of Lean generated; ~6 billion output tokens consumed. No prior AI math formalization has operated at this scale.
- **P2M dependency DAG**: the pipeline maintains a directed acyclic graph of theorem statements, enabling parallel agent work while tracking dependencies and preventing duplicate effort — structurally similar to a build graph but for mathematical proofs.
- **External correctness oracle**: the Lean kernel is a third-party verifier that the agents cannot influence. Every declaration must pass kernel checking; the proof uses only `propext`, `Classical.choice`, and `Quot.sound`. There is no self-reported accuracy — correctness is structural.
- **Three independent verification layers**: Lean kernel + comparator + nanoda Rust kernel. The redundancy is unusual and reflects the stakes of the claim.
- **Attribution infrastructure**: 106 upstream files explicitly traced with copyright preservation; dependency graphs displayed per-theorem in the HTML interface (390 MB, offline-browsable).
- **Multi-agent coordination without a shared workspace**: agents build proofs that cite other proofs via formal theorem names, not shared memory — the dependency structure IS the coordination mechanism.
- **The proof is closed**: 641 stars, no open issues, no PRs accepted. This is a research artifact, not a maintained project.

## Why clawfit should care

The P2M pipeline demonstrates that multi-agent systems can sustain coherent work across 11 days and 30,000 subtasks without human intervention. The implications for clawfit:

1. **Long-horizon task type**: clawfit's `task` taxonomy covers qa, code-gen, documentation, planning, research. Mathematical proof formalization is a distinct task class — high-precision, formally verifiable, multi-week horizon. Whether this warrants a new registry dimension (`formal_verification`, `long_horizon`) is an open question, but P2M is the clearest existence proof that such tasks are agent-tractable.

2. **DAG-governed multi-agent coordination**: the P2M architecture — agents work on leaf nodes, results propagate up a dependency tree, redundant paths pruned automatically — is a pattern applicable to any decomposable long-horizon task (e.g., large codebase refactors, multi-document synthesis). This is qualitatively different from the concurrent-critique pattern (IBM Bob, HydraFusion) tracked in the September 4 scan.

3. **Verification-first output discipline**: agents produce Lean code that either compiles or fails — there is no ambiguous partial credit. This "verifiable output" constraint likely drives qualitatively different agent behavior than prose or code generation where correctness is evaluated post-hoc by humans. Relevant for clawfit profiles that require high-precision outputs.

## Preliminary interpretation

Current best reading:
- **Level 2 — Multi-agent harness (primary)**: P2M orchestrates a fleet of Claude agents against a DAG of proof obligations. The harness handles work distribution, dependency tracking, and citation management — canonical L2 orchestration.
- **Level 3 — Workflow / governance layer (secondary)**: the dependency DAG defines a behavioral specification for the agents — which theorems to prove next, which to defer, which are blocked by unproved citations. This is L3 workflow governance applied at mathematical scale.

## Claims to verify

- Whether the P2M platform is being released as an open tool or remains internal to Anthropic (the repo contains the output artifact, not the orchestration code)
- Whether the 6 billion output tokens figure implies a frontier model cost that would be prohibitive for any non-research use of this architecture
- Whether the three-independent-verification setup is transferable to other domains (Lean kernel is domain-specific; other formal verification systems would need equivalent external oracle)
- The 11-day wall-clock time: whether this implies continuous agent operation or significant idle time between subtask batches

## Status

- 641 stars, 43 forks — research artifact; not maintained, not accepting contributions
- Not eligible for clawfit registry: formal math proof is not a task type in the current schema; no public API or inference cost data for the P2M harness
- First tracked example of a dependency-DAG multi-agent coordination pattern producing formally verified output at research scale
- Watch for: open-sourcing of the P2M orchestration layer; follow-on projects applying this pattern to other formal verification tasks; star growth indicating practitioner adoption interest
