# Research Watch: Vibe-Trading — Multi-Agent Finance Workspace

- Repo: https://github.com/HKUDS/Vibe-Trading
- Also see: https://github.com/HKUDS/ClawTeam (swarm orchestration sibling from same org, 5.1k★); https://github.com/HKUDS/nanobot (ultra-lightweight agent sibling); https://github.com/HKUDS (Data Intelligence Lab @ HKU org page); `docs/research-watch/2026-05-05-dexter-financial-research-agent.md` (single-agent finance CLI, L1, 23k★); `docs/research-watch/2026-05-01-tradingagents-financial-multiagent-framework.md` (multi-agent trading harness, L1/L2, 57k★); `docs/research-watch/2026-05-06-anthropics-financial-services.md` (1st-party domain skill pack, L4b, 8.5k★)

## Why this is worth watching

Vibe-Trading is the fourth high-signal finance-domain entry in the current watch queue (after Dexter, TradingAgents, and anthropics/financial-services) and is structurally distinct from all three: it ships as a self-contained finance workspace that spans L2 swarm orchestration, L4 skill registry, and L5 MCP surface in a single install, rather than occupying a single layer. At 6.2k stars (1.2k forks) with v0.1.7 released May 2026, the project is young but the institutional origin — HKUDS (Data Intelligence Lab, HKU) rather than an individual developer — gives it a different credibility profile than community finance agents. The ClawHub one-command installation and the 22-tool MCP exposure targeting Claude Desktop and Cursor place it directly in the MCP-first distribution channel that is growing fastest in this taxonomy.

## What stands out immediately

- **Dual surface: standalone agent workspace + MCP server.** Vibe-Trading can be run as a full local web app (FastAPI backend + React 19 frontend) or installed as a stdio MCP subprocess exposing 22 tools to Claude Desktop, Cursor, or OpenClaw. This is not a common design at this layer — most financial agent projects choose one deployment model. The MCP path means a user can invoke backtesting, swarm launching, and pattern recognition from inside Claude without installing the full stack. "21 of 22 tools work with zero API keys" for HK/US/crypto markets is a claim to inspect, but if accurate, it substantially lowers the entry barrier vs. TradingAgents or Dexter (both of which require API key configuration before any data flows).
- **74 specialist skills across 8 domains.** Skills are organized as discrete callable units covering: data sourcing, strategy generation, fundamental analysis, asset classes, crypto, flows, tools, and risk analysis. This is the largest finance skill library tracked in this taxonomy to date — the anthropics/financial-services pack ships 50+ commands across 7 verticals; Dexter ships 2 built-in skills (dcf, x-research). Structural relationship of "skills" to the 27 bundled agent tools is not clearly documented — skills appear to be higher-level callable recipes while tools are the underlying agent primitives. Requires source inspection to confirm.
- **29 pre-configured swarm team presets, not dynamic swarm construction.** These are workflow templates, not a runtime swarm builder. Named examples include `investment_committee` (bull/bear debate → risk review → PM final call), `global_equities_desk` (A-share + HK/US + crypto researcher → global strategist), and `quant_strategy_desk` (screening + factor research → backtest → risk audit). Each template defines a fixed agent-role topology and a communication flow. DAG-based orchestration is claimed but the degree to which swarm graphs are truly dynamic vs. static templated topologies is not confirmed from README alone. Treat "DAG orchestration" as a design claim pending source inspection.
- **7 market-specific backtesting engines + composite cross-market engine.** Covers A-shares (Tushare), HK/US (yfinance), crypto (OKX, CCXT, 100+ exchanges), futures, and forex. Automatic fallback chains across 6 data sources. 15+ performance metrics and 4 portfolio optimizers (MVO, equal volatility, maximum diversification, risk parity). This is the most complete backtesting surface of any agent project in this taxonomy; TradingAgents and Dexter have no comparable backtesting infrastructure. Claim to inspect: "7 market engines + composite cross-market engine with shared capital pool" — the shared capital pool implies cross-asset position accounting, which is architecturally non-trivial.
- **ReAct agent with 5-layer context compression and FTS5 cross-session memory.** The agent core is a single ReAct loop (not a multi-agent architecture at the individual-agent level), augmented with persistent cross-session memory via FTS5 full-text search over conversation history. This mirrors Dexter's scratchpad compaction approach. The "5-layer context compression" is not detailed in available documentation — claim to inspect.
- **HKUDS ecosystem framing: ClawTeam + NanoBot + Vibe-Trading + ClawHub.** The org's repos collectively form a layered stack: NanoBot (minimal agent kernel, L1 analog), Vibe-Trading (domain workspace with skill layer), ClawTeam (swarm orchestration framework, 5.1k★), and ClawHub (skill marketplace enabling `npx clawhub@latest install vibe-trading --force`). ClawHub is a direct structural analog to a package registry for agent skills. The presence of a distribution/discovery layer (ClawHub) and a coordination layer (ClawTeam) alongside the domain application suggests the HKUDS lab is building a complete stack, not just a demo.
- **Security posture is hardening in v0.1.7.** Recent release added explicit CORS origins, 1MB upload limits, gated shell tools, and `API_AUTH_KEY` for remote deployments. Shell tool gating and CORS controls are not present in comparable early-stage finance agent projects. This is a structural quality signal even at v0.1.x.
- **No published performance benchmarks or backtesting results.** The README includes a disclaimer ("not investment advice, does not execute live trades") but cites no strategy backtest results, no sharpe ratios, no comparison against benchmarks. Backtesting infrastructure exists but no evidence that the authors have used it to validate any included strategy skill. This is a material gap relative to the marketing framing.

## Preliminary interpretation

Current best reading:

- **Level 2 — Meta wrappers / harnesses / orchestration layers** (primary). The 29 swarm team presets with DAG-based multi-agent coordination, the swarm launcher as one of the 27 bundled tools, and the real-time streaming dashboard for live agent status collectively constitute an orchestration harness over multiple subordinate agents. The topology is pre-configured rather than dynamically composed, which is a weaker form of L2 than Ruflo (which builds swarm topologies at runtime) — call this a **template-driven swarm harness** sub-type, distinct from dynamic orchestrators. The swarm layer wraps a single-agent ReAct core, making L2 the harness wrapper and L1 the underlying individual agent.
- **Level 4 — Capability / skill / plugin / tool-use layer** (secondary). 74 specialist finance skills and 27 bundled tools constitute a domain skill library comparable in scope to anthropics/financial-services (50+ commands) and exceeding Dexter (2 skills). The ClawHub packaging — installable as a discrete skill bundle — reinforces the L4 reading. Unlike anthropics/financial-services (which is a L4b skill pack primary), Vibe-Trading uses the skills in service of L2 swarm coordination rather than exposing them as the primary deliverable. Secondary L4 classification is appropriate.
- **Level 5 — Memory / MCP / context layer** (secondary, MCP surface). The 22-tool MCP server exposure is a genuine L5 surface — it places the entire backtesting and swarm infrastructure into the MCP tool layer accessible from any compatible client. This is the strongest MCP distribution play seen in the finance cluster to date. The ReAct agent's FTS5 cross-session memory is also an L5 component, though lighter than Ruflo's HNSW/AgentDB substrate.

Sub-type: **domain-vertical swarm workspace with MCP server distribution** — distinct from single-agent domain CLIs (Dexter), multi-agent trading harnesses without skill registries (TradingAgents), and domain skill packs without runtime orchestration (anthropics/financial-services).

Regarding reference-levels.md: this signal reaches the threshold to flag the **template-driven swarm harness** pattern as a named L2 sub-type alongside dynamic orchestrators (Ruflo) and production-SDK harnesses (deepagents). However, at v0.1.7 with 6.2k stars, unverified backtesting claims, and no independent benchmark data, the entry does not yet clear the bar for promotion. Do NOT modify reference-levels.md at this time. Flag for re-evaluation at v0.3.0 or 15k stars, whichever comes first.
